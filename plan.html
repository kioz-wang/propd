2 IO PDU & C/S 时序

请求头布局

io_package_t  269 字节  __attribute__((packed))

  Offset   Bytes   Field
  ─────────────────────────────────────
     0       1     type          io_type_t (get=0 set=1 del=2 info=3)
     1       8     created       timestamp (ns)
     9     255     key[]         NAME_MAX, 零填充
   264       5     value         仅 header: type(1B) + length(4B)
  ─────────────────────────────────────
  + 可选: value.length 字节数据 (仅 _io_set)

get 时序

Client

T1 us_open_at() → connect
T2 io_begin(_io_get)
T3 us_read(duration, 8B)
T4 us_read_auto(value)
T5 us_read(result, 4B)
T6 us_close()
⇄

Server

— accept() → thread_pool
— recv(pkg_head, 269B)
— cache_get → ENOENT
— route_match → &storage
— named_mutex_lock
— prop_storage_get()
— send(duration) ← handler 内!
— send(value)
— send(result) ← worker 循环
— recv(下一个请求)
⚠ 不对称: handler 直接 send() duration+value (①②段), worker 循环 send result (③段)。发送逻辑分散在两个函数里。

set 时序

C→us_write(pkg_head, 269B)
C→us_write(value_data, len)
S:recv → malloc(value) → cred_check → io_set()
C←us_read(result, 4B)
⚠ ENOMEM bug: malloc 失败后 server 直接 return，不 send result。客户端在 io_end() 永久阻塞。

del / info 时序

del: 请求 → io_del() → result。info: 请求 → range → choices[N] → help → chain[N] → result。

4 注册 / 反注册机制

问题严重度描述
组包/解包无封装 P1 每个 API 重复 ctrl_init → 填字段 → ctrl_update → ctrl_final0。register_child 自己写 ~25 行填充逻辑
解包无边界校验 P0 register_child() 直接用 child->num_prefix 遍历数组，未检查 (N+M)×255 ≤ recvfrom 收到的字节数
io_update 同步阻塞 P1 Ctrl worker 中 io_update() 连接子节点并等待响应，慢子节点卡住线程池
反注册 zombie 缺失 P1 nref > 0 直接 EBUSY。建议: zombie 标记，route_deref 自动清理

6 Append 模式 P1

新增 _ctrl_register_child_append (type=6)，包结构复用 ctrl_package_register_child_t。

模式注册名已存在注册名不存在
普通 (type=0)清理旧的，创建新的创建新的
追加 (type=6)追加 prefix / cache_now返回 ENOENT
# 启动时核心注册
prop ctrl register_child db-server /db/* /config/*

# 运行时热加载新模块
prop ctrl register_child_append db-server /metrics/* /health/*

不需要协议层分片；一次 append 装不下由调用方多次 append。

8 改进建议

统一 IO 响应 P0

struct io_response {
    int32_t     result;        // 4B
    timestamp_t duration;      // 8B  (非 get 时为 0)
    uint32_t    value_length;  // 4B  (0 = 无 value)
    uint8_t     value[];       // value_length 字节
};

handler 不再直接 send，所有输出由 worker 循环统一发送。

ENOMEM 也要 send result P0

if (!value) {
    logfE("no memory");
    int err = ENOMEM;
    send(connfd, &err, sizeof(err), MSG_NOSIGNAL);  // ← 新增
    /* discard client value data */
    return ENOMEM;
}

字段重命名 P0

当前 (误导)→ 建议
value_t value;value_type_t value_type; uint32_t value_length;

Ctrl 加 payload_length P1

struct ctrl_package {
    ctrl_type_t type;
    uint16_t    payload_length;   // ← 显式声明变长部分大小
    union { ... };
};

目标协议 v2 (远期)

// IO 请求 (变长)
struct io_request {
    io_type_t   type;          // 1B
    timestamp_t created;       // 8B
    uint16_t    key_length;    // 2B
    uint32_t    value_length;  // 4B
    char        key[];         // key_length 字节
    // 后跟 value_length 字节数据
};
